## Result and approved contract

Both `tr-chat` and `tr-chat-ui` now support three DOM scoped Renderers—`sender-actions-inline`, `sender-footer`, `sender-footer-right`—and a native composer inside a custom DOM welcome Renderer. The implementation reuses native Sender editing and internal Vue composition. Public DOM contexts expose no editor, VNode, Ref or component instance.

The approved ownership rules are implemented:

- Scoped operations edit immediately through native Sender and emit native update requests. For controlled `tr-chat-ui`, Angular owns accepted `inputValue` and writes it back; operations are not a veto/transaction API.
- `ChatSenderRendererContext` exposes boolean `disabled`, `loading`, `hasContent`, plus `focus(): Promise<boolean>`, `blur()`, `insert()`, `append()` and `replace()`. Disabled/retired editing handles are inert; retired focus resolves false. Each context belongs to its Renderer invocation.
- `ChatEmptyStateRendererContext.renderComposer()` returns a DOM container or null. Call it synchronously and include the returned container in the Renderer result. Repeated calls during that invocation return the same target. An omitted target, failed Renderer or `sender: false` mounts no hidden editor.
- An outer welcome Renderer invocation owns one native editor. Ordinary draft/UI-option updates and Runtime adapter model/attachment changes preserve that editor, focus and composition. Explicit Renderer replacement, explicit host data refresh, relevant welcome-context changes or Runtime replacement can retire the invocation. Draft and attachments are restored; selection and IME state are not preserved across explicit teardown.
- Native Vue slots retain precedence. On custom elements, static footer slots are fallback when the matching scoped Renderer is absent. Native toolbar, attachment and submit behavior remain available.

The two selected P1 gaps are closed within these boundaries. Full `sender-content` rich-editor replacement remains a separate contract design task.

## Failures found and corrected

- TDD first exposed missing scoped controls and welcome composition. Real native editor tests drove the implementation, rather than testing only wrapper callback calls. Early selection setup assumed keyboard Home selected the intended text; it now installs a real DOM Range and positively verifies the selection. Demo controls were shortened/wrapped to keep real click targets usable.
- Function wrappers initially hid same-key Renderer identity changes. Tracking the actual callback fixes replacement/abort. Equal-empty-view Runtime replacement also required explicit Runtime ownership so stale methods cannot target a replacement editor.
- Semantic welcome comparison initially suppressed explicit retained-history refresh. Tracking host source data fixes that regression. Treating every source object as explicit then remounted the editor during adapter-generated model/attachment changes; private Runtime adapter ownership distinguishes those changes, with regression coverage for both requirements.
- Real Angular restoration revealed consecutive-space loss. The first raw-string full-whitespace fix changed inline HTML parsing under the installed Tiptap version. Schema parsing to a document before native `setContent` resolved both requirements. The independent reviewer additionally checked spaces, tabs, newlines, inline HTML and script-tag input across initial/model/method paths, including silent model updates.
- A browser draft check initially used `textContent`, which concatenates native paragraphs. The validator now uses `innerText` for logical editor draft text and compares Angular's raw output directly. This assertion correction does not relax consecutive-space restoration coverage.
- Screenshot review found cramped mobile demo content and the optional word counter outside the desired card bounds. Supported demo options/frame dimensions were adjusted and all three apps rebuilt. The final stricter button check initially counted a hidden zero-size attachment preview button; filtering absent layout boxes fixed that false failure. Every visible button remains checked.
- Final repository E2E reported the existing multi-line placeholder case `src/sender/specs/basic.spec.ts:146` as flaky. Its first run failed; the serial group was replayed and the case passed on retry. Final output is **158 passed, 1 flaky**, not a clean159 first-pass result. No production change was made to hide this result.
- Browser localhost binding fails with `EPERM` inside this sandbox, and Angular native build tooling aborts there. Browser checks and Angular builds ran outside the sandbox. Dependency installation used escalated pnpm as required; offline source checks remained inside unless restricted.
