Date: 2026-11-13. Baseline: upstream `v1.0.1`, HEAD `9ae04e097ad723a376ce5402790375a2b0f5242e`. ## Result

Implemented the next native public-capability parity batch: composer DOM methods, sender drag/paste details, tri-state/boolean empty-state handling, native input-prefix content, extension renderer metadata and DOM-compatible listener types. Both tags pass the affected-capability matrix in Angular 20 Standalone, NgModule and SSR/hydration hosts. Final component suite: **505/505 passed, with no retries used**; unit 102/102, repository E2E 159/159 and Angular business 27/27. Nine inspected screenshots, consumer provenance and executable demo/validation sources are retained below. Remaining scoped-composer composition, distribution and SSR boundaries are explicitly separated from missing validation evidence.

## Selected implementation boundary

Reuse native Vue methods and event payloads; add no parallel composer state or business logic. Add the missing empty-state override with the native `undefined` default. Consumers call DOM methods after readiness, assign complex values as DOM properties, and read event payloads directly from `CustomEvent.detail`. Controlled `tr-chat-ui` continues to request updates; the host decides when to write `inputValue` back.

The DOM typing issue was discovered by the real Angular demo: custom-only `addEventListener`/`removeEventListener` declarations made the interfaces structurally incompatible with `Node`. The new compiler test first failed on `append`, native event names and generic listeners, then passed after restoring DOM overloads. Custom detail inference remains first in overload resolution.

Read-only review found one P2 issue: `is-empty=""` rendered true but left the public getter as an empty string. This was reproduced against the installed Angular candidate (`'' !== true`), fixed by adding `isEmpty` to both existing boolean synchronization lists, and covered by attribute/toggle/removal acceptance tests. Followup review found no remaining actionable issue in the changed contracts.

## Validation failures and corrections

- The first browser-test launch could not bind `::1:3100` inside the sandbox (`EPERM`). Real-browser checks ran outside it. Angular native build tooling also aborted inside the sandbox; outside-sandbox production builds passed. These were execution-environment failures, not failed product assertions.
- An npm install attempted against an existing pnpm-layout fixture failed in npm Arborist (`Cannot read properties of null (reading 'matches')`). The fixture was installed successfully with its original pnpm lock/layout. This report does not claim a fresh npm consumer validation for this batch.
- The first new slot test appended content after connection. Inspection of Vue's installed CE slot collector showed that static light-DOM content is collected on connection. The fixture now supplies initial slot children before append, as the existing static-slot contract requires.
- The Angular demo initially combined incompatible generic listener overloads on an element union, used dot notation for dataset index signatures, and needed correct NgModule import wiring. These demo issues were corrected. The separate DOM-node incompatibility was a real declaration defect and received a permanent compiler regression test.
- Early repository E2E hit native Sender's multi-line placeholder case (132 passed, 1 failed, 26 skipped by serial grouping); a full rerun passed 159/159 without production changes.
- Parallel component runs exposed timing sensitivity in native scrolling tests. One run passed 503/503 before the final two boolean cases were added. Later runs recorded 504/505: initially `useAutoScroll / preserves the reading position after the user scrolls upward` observed 300 instead of 200; after replacing synthetic scroll mutation/dispatch with actual wheel input, that test passed 10 repeated checks. A subsequent parallel run and a serial run failed `changing the scroll root invalidates pending recovery and rebinds it to the current container` (2638 instead of 2332; 504/505 each). Isolation reproduced the setup race. Temporary root/subtree scroll-anchoring opt-outs did not fix it and were discarded. Tracing showed an initial queued application auto-scroll returning the test to the actual bottom before renderer pause; the production code then correctly resumed from the bottom. The test now uses real wheel input, positively verifies distance=200 before pausing, and retains settling and its original rebinding assertions. Ten repeated checks passed. All tracing/opt-outs were removed, and no native scrolling production code changed. After both setup corrections, the next full run passed both scroll scenarios but finished 504/505 on `ModelSelectorFlows / disabled models cannot be selected with pointer or keyboard`: after End/Enter the event output was `[]` instead of `["model:beta"]`. That case passed immediately in isolation (1/1), with no Model Selector source/test changes. The final full run using the existing CI retry allowance passed **505/505 with no retries invoked**; all earlier failures remain disclosed.
- Screenshot review caught Runtime card overflow in the demo. The existing container-height CSS variable fixed it, and geometry acceptance now checks vertical content boundaries. The validator positively waits for Angular draft writeback and a usable native Send control before capture.
