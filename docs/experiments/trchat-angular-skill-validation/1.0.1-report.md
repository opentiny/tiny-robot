# TrChat Angular 1.0.1-based Web Component validation

## Conclusion and version boundary

The Angular integration paths passed against a **locally packed Web Component candidate based on upstream `v1.0.1`**. The published registry artifact `@opentiny/tiny-robot-chat@1.0.1` does not publish `./experimental` or `./experimental/web-component.css`; this report does not claim that the registry package supports the Web Component. The tested candidate combines the stable 1.0.1 source baseline with this branch's Web Component implementation.

The upstream diff from `v1.0.0-rc.9` to `v1.0.1` contains package/release metadata changes but no source changes under `packages/chat/src`, `packages/components/src`, or `packages/kit/src`. No TrChat public runtime API migration was required. The candidate package versions, internal dependency graph, Angular Skill and consumer verifier were upgraded to `1.0.1` and revalidated.

Standalone, NgModule, and SSR/hydration met every applicable criterion in the frozen [1.0.1 rubric](1.0.1-rubric.md). No real DeepSeek key or remote provider was used. Provider, MCP, Skill, history, renderer, attachment and model-feature flows used deterministic local services.

## Validation issue found

The full Standalone suite initially timed out in the read-aloud scenario because the test clicked a renderer-created button while the streamed response was still replacing that renderer node. The action passed in isolation but failed during the full suite. The temporary acceptance fixture was corrected to positively wait for Runtime request state `completed` before clicking the read-aloud action. No production source was changed for this fixture timing issue; the complete 27-test suite then passed.

## Remaining limits

- The registry `@opentiny/tiny-robot-chat@1.0.1` remains unusable for this Web Component integration because it lacks the experimental exports. Consumers must continue using the locally packed candidate until a later published version includes them.
- The Standalone initial browser bundle is 2.25 MB and exceeds its warning budget by 54.19 kB, while remaining below the configured error budget.
- The NgModule fixture retains `skipLibCheck: true` for candidate/Vue-generated third-party declaration compatibility. Angular strict templates and the real NgModule schema boundary compile successfully.
- SSR validation covers client-created TrChat inside an Angular hydration boundary, not server-rendered TrChat markup. The runtime snapshot begins with zero conversations; business sending, history, MCP and Skill flows are covered by the Standalone fixture.
- The 390 px NgModule heading wraps across lines but remains within its container; geometry checks report no document-level horizontal overflow.
- No real DeepSeek credential, remote DeepSeek response, native operating-system file picker or remote MCP server was exercised.

No package was published, no release tag was created, no branch was pushed and no publish CI was triggered during this validation.
