## 核心定位

OpenTiny 的公开表达集中在“企业级前端开发解决方案”。GitHub 组织描述把 OpenTiny 定义为一套企业级前端开发解决方案，产品覆盖 TinyVue、TinyNG、TinyEngine、TinyTheme、TinyPro、TinyCLI 等工具链；官网首页标题进一步强调“企业级产品的完整设计和开发解决方案”。

更适合文章复用的定位句：

- OpenTiny 是面向企业级应用的前端开发解决方案，覆盖组件库、低代码、主题配置、中后台模板、AI 交互和前端智能化工具。
- TinyVue 是 OpenTiny 的核心 UI 组件库，主打跨端、跨框架，支持 Vue 2、Vue 3、PC 端和移动端。
- OpenTiny NEXT 面向前端智能应用，围绕生成式 UI、WebMCP、NEXT-SDKs、TinyRobot 等方向推进 Agent 时代的前端体验升级。
- TinyEngine 是低代码引擎，强调“使能开发者定制低代码平台”。

## 产品生态

| 产品 | 文章中的角色 | 可复用表达 |
| --- | --- | --- |
| TinyVue | 核心组件库 | 企业级 UI 组件库、跨端跨框架、PC/Mobile、多技术栈适配 |
| TinyEngine | 低代码引擎 | 在线构建低码平台、支持二次开发、适合定制领域低代码平台 |
| TinyRobot | AI 对话组件库 | 快速构建企业级 AI 助手、智能客服、多轮对话系统 |
| GenUI SDK | 生成式 UI SDK | 让 AI 从文本输出走向动态 UI 渲染，适配 Vue、Angular 等场景 |
| NEXT-SDKs / WebMCP | 前端智能应用工具包 | 让前端页面接入 AI Agent，支持浏览器自动化和智能体操控界面 |
| TinyEditor | 富文本编辑器 | 基于 Quill 2.0，强调功能强大、开箱即用 |
| TinyCharts | 图表库 | 前端可视化、主题定制、响应式、兼容 ECharts API |
| TinyPro / TinyCLI / TinyTheme | 效率工具 | 中后台模板、工程脚手架、主题配置系统，提高研发效率 |

## 表达模式

### 1. 先讲业务痛点，再接产品方案

官网和掘金文章都偏向从企业应用、控制台、跨端适配、AI 改造等场景切入，再引出 OpenTiny 产品。文章开头可以先写开发者遇到的问题，再说明 OpenTiny 如何降低接入、开发或维护成本。

### 2. 强调“完整生态”，不要只讲单点组件

OpenTiny 的品牌资产不是单一组件库，而是从组件、低代码、主题、工程化、AI 交互到智能化改造的一组工具。写文章时应把单个产品放进生态中解释：TinyVue 解决 UI 基础能力，TinyEngine 解决低代码搭建，TinyRobot / GenUI SDK / NEXT-SDKs 解决 AI 时代交互和 Agent 接入。

### 3. 技术价值与体验价值并重

官方表达同时出现“前端最佳实践”“企业级开源体验设计系统”“提高开发效率”“用户体验可度量、可监控、可优化”等口径。文章不宜只写 API，也要交代体验收益、维护收益和团队协作收益。

### 4. 社区语气要有参与感

掘金文章会感谢贡献者、邀请加入官方交流群、放出官网和 GitHub 仓库链接。发布类文章结尾适合用社区 CTA：欢迎体验、Star、提 Issue、加入交流。

## 建议口径

- 用“OpenTiny 社区”称呼面向外部开发者的主体。
- 产品名保持英文原文：`OpenTiny`、`TinyVue`、`TinyEngine`、`TinyRobot`、`GenUI SDK`、`OpenTiny NEXT`、`NEXT-SDKs`、`WebMCP`。
- 中文说明优先服务读者理解，不硬译 `Agent`、`SDK`、`MCP`、`Playground`、`renderless` 等术语。
- 面向官网、README、PRD 时语气克制；面向掘金文章时可以更具传播感，但仍要落在真实功能和开发者收益上。

## 避免

- 不把 OpenTiny 简化成“Vue 组件库”；它的公开定位明显更宽。
- 不使用无依据的“国内第一”“最强”等绝对化表达。
- 不堆砌 AI 概念；需要落到具体能力，如流式渲染、Agent 接入、WebMCP、UI 组件、Playground。
