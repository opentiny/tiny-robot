03

整体架构

从页面到外部服务，Chat 用一条清晰的数据流串起多个可替换模块。

分层图 · UI、Runtime 与基础服务的调用方向

flowchart LR ui["TrChatUI<br/>Layout · Messages · Composer"] --> trchat["TrChat<br/>事件与动作编排"] trchat --> adapter["useChatRuntimeAdapter<br/>状态投影 · 草稿 · 错误"] adapter --> runtime["ChatRuntime<br/>会话 · Composer · actions"] runtime --> kit["Kit<br/>Conversation · Message Engine"] kit --> services["Provider / MCP / Storage"]
层输入输出不负责什么
TrChatUI只读 Data、UI Options、输入值UI 事件不请求模型、不保存会话、不处理业务 pending
TrChatUI 事件、ChatRuntimeRuntime 动作、公共事件不实现消息引擎
AdapterRuntime 可读状态和动作ChatUIData、草稿和错误投影不决定业务数据源
ChatRuntime会话和 Composer 依赖统一状态协议与动作协议不限定 UI 结构
Kit / Provider / MCP消息、请求和工具配置流式消息、工具结果、持久化不决定页面布局
替换点： 新项目可以使用 useLocalChatRuntime；已有 Kit 会话可以使用 useKitChatRuntime；其他数据层只需要实现 ChatRuntime。
05

契约边界

公开协议越小，替换成本越低；实现细节留在各自的包内。

ChatRuntime

状态和动作

interface ChatRuntime {
  conversations: ChatReadable<readonly ChatConversationInfo[]>
  activeConversation: ChatReadable<Conversation | null>
  composer: ChatComposerRuntime
  actions: ChatRuntimeActions
}

外部只需要关心当前会话、Composer 条件和动作入口。

ChatUI

数据和配置

interface ChatUIProps {
  data?: Readonly<ChatUIData>
  ui?: Readonly<ChatUIOptions>
  inputValue?: string
  defaultInputValue?: string
}

UI 不要求数据必须来自 Vue Ref，也不要求宿主使用 Kit。

06

一条消息的完整生命周期

发送不是一个组件方法，而是一条从草稿、Runtime 到流式消息渲染的数据链路。

流程图 · 从用户输入到流式消息渲染

flowchart LR input["用户输入"] --> composer["ChatComposer"] composer --> ui["TrChatUI<br/>submit"] ui --> draft["useChatDraft<br/>trim · clear · restore"] draft --> adapter["Adapter"] adapter --> send["runtime.actions.send"] send --> engine["Kit Message Engine"] engine --> provider["Provider<br/>SSE"] provider --> data["ChatUIData"] data --> render["ChatMessages<br/>重新渲染"] send -.->|reject| error["request error<br/>runtime-action-error"] error -.-> draft
true

Runtime 接受发送

已通过非空、disabled、submitDisabled 等前置条件，消息进入请求流程。

false

没有创建消息

资格不满足。草稿层会恢复提交前文本，页面不会伪造一条消息。

reject

请求或引擎失败

Runtime 记录错误，Adapter 报告动作错误，草稿恢复并展示 request error。

为什么先清空草稿

提交后的输入区立即回到可继续输入的状态；如果发送未被接受或发生异常，再由 useChatDraft 恢复旧值。

为什么先 trim

空白文本不应该创建会话或消息；标题生成也使用有效文本，避免出现空标题。

取消请求

Footer 的 cancel 事件经 Adapter 调用 runtime.actions.abort，底层 AbortSignal 停止当前请求，状态进入 aborted。

流式更新

Message Engine 将响应块持续写入当前消息，Kit 的响应式消息变化向上投影，UI 只负责重新渲染。
