如何接入

按数据层的现状选择入口，不需要为了使用 Chat 重写已有消息系统。

useLocalChatRuntime + TrChat

适合新项目。Chat 负责创建 Conversation、接入 Provider，并可选装配 MCP。

App.vuepackages/chat-basic/src/App.vue
<script setup lang="ts">
import { TrChat, useLocalChatRuntime } from '@opentiny/tiny-robot-chat'

const runtime = useLocalChatRuntime({
  modelProviders: [
    {
      type: 'openai',
      apiUrl: '/api/chat',
      models: [{ id: 'demo-model', label: 'Demo Model' }],
    },
  ],
})
</script>

<template><TrChat :runtime="runtime" /></template>

useKitChatRuntime + TrChat

适合已经使用 Kit Conversation、已有存储策略或已有 responseProvider 的项目，复用既有消息和会话逻辑。

已有 Conversationpackages/chat/docs/chat-runtime-design.md
const conversation = useConversation({
  storage,
  useMessageOptions: { responseProvider },
})

const runtime = useKitChatRuntime({
  conversation,
  titleGenerator: (text) => text.trim().slice(0, 20),
})

自定义 ChatRuntime + TrChat

适合已有后端状态管理、企业数据层或非 Kit 消息引擎的项目。实现公开协议后，UI 不需要知道底层差异。

宿主数据层packages/chat/src/types/runtime.ts
const runtime: ChatRuntime = {
  conversations,
  activeConversation,
  composer,
  actions: {
    send,
    abort,
    createConversation,
    switchConversation,
    renameConversation,
    deleteConversation,
  },
}
14

设计优点与当前边界

好的抽象不仅说明能做什么，也要明确哪些事情应该留给宿主和后端。

Strengths
分层UI、适配、Runtime 和引擎职责清晰。
可替换支持 Local、Kit 和自定义 Runtime。
可扩展Options、Events、Slots 覆盖不同产品形态。
Boundaries
服务协议特殊 Provider 或 MCP 协议需要自定义适配。
运行环境浏览器直连存在 CORS、认证和容器高度限制。
企业能力权限、审计、OAuth 和连接复用由宿主或后端处理。

后续计划

路线从当前已有的 Runtime、Provider、MCP 和 UI 扩展能力自然延伸。

近期 / 稳定基础

  • 完善 API、Runtime 和 MCP 文档
  • 补充核心交互与集成测试
  • 统一错误、加载和取消状态
  • 完善 Provider 配置和 BFF 示例
  • 正式提供 ModelSelector 原子组件，统一不同产品的模型切换体验

中期 / 扩展能力

  • 扩展更多模型协议和请求映射
  • 完善 MCP 权限、筛选和配置体验
  • 增加附件、引用和结构化输入
  • 提升移动端、主题和可访问性

长期 / 平台能力

  • Runtime 插件化和更完整的工具编排
  • 多模态消息和更丰富的内容协议

核心结论

Chat 以 components + kit 为基础，将聊天 UI、Runtime 和模型接入组织成统一的应用层。同时，CLI 将标准实现交付给新项目和存量项目。

components + kit→Chat→chat-cases→CLI
