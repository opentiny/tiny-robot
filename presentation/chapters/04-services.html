05

Provider 与模型能力

Provider 把统一的 Chat 请求转换成具体模型服务理解的请求，并将流式结果交回消息引擎。

配置层

ChatProviderConfig 描述 Provider 类型、地址、请求头和模型列表；模型通过 capabilities 声明 thinking、search 等能力。

openaiOpenAI 兼容 Chat Completions 接口。
deepseek支持 thinking 请求体和 reasoning effort。
qwen支持 thinking、search 请求字段映射。

运行层

用户选择的模型和能力进入本轮 runConfig。Provider Request Plugin 将其映射为请求字段，Response Provider 发送 POST 流式请求并解析 SSE。

边界：浏览器端的 API Key 会进入客户端环境。生产环境应通过 BFF 或后端代理完成认证和请求转发。
最小接入示例packages/chat/src/runtime/useLocalChatRuntime.ts
const runtime = useLocalChatRuntime({
  modelProviders: [
    {
      type: 'openai',
      apiUrl: '/api/chat',
      models: [
        {
          id: 'demo-model',
          label: 'Demo Model',
        },
      ],
    },
  ],
})
capabilities

控制可见能力

只有当前模型声明支持的能力才会出现在 Composer 控件中。

featureBody

控制请求字段

能力名称和真实 Provider 字段解耦，允许按模型覆盖映射。

stream

持续更新消息

SSE 块由 Kit 消息引擎消费，页面不需要直接处理网络连接。

10

MCP 设计

MCP 把外部工具纳入当前轮请求，但不把外部服务的连接细节泄漏到 UI。

流程图 · MCP Server 到模型 Tool Call 的生命周期

flowchart LR config["mcpServers<br/>配置 Server"] --> adapter["MCP Adapter<br/>安装 / 启用"] adapter --> discovery["Tool Discovery"] discovery --> tools["可用 Tools"] tools --> snapshot["本轮 RunConfig<br/>serverIds · toolIds"] snapshot --> engine["Message Engine"] engine --> model["模型"] model -->|Tool Call| adapter adapter -->|Tool Result| model model --> answer["继续生成回答"]
Recommended

mcpServers

适合浏览器可访问的远程 Streamable HTTP MCP。Chat 创建默认 Adapter，负责 discovery、工具状态、超时和按需关闭 Client。

生产场景推荐将地址指向 BFF，由后端处理密钥、OAuth、CORS、权限和审计。

Advanced

自定义 mcp Adapter

适合 stdio、旧 SSE、OAuth、企业网关、连接复用或自定义权限系统。宿主提供 runtime、listTools 和 callTool。

默认 Adapter 不启动本地进程，也不负责保存长期凭证。

发送保护：已启用 Server 但 Tool 尚未加载完成时，Runtime 派生的 submitDisabled 会阻止发送；加载失败会记录 Server 错误并自动禁用。
