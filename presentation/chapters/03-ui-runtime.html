04

核心设计：UI、Adapter 与 Runtime

ChatUI 是一个不依赖 Runtime 的聊天页面 Shell：它描述“怎么呈现”，不决定“数据从哪里来”。

契约表达内容典型字段变化来源
ChatUIData当前展示事实messages、loading、selectedId、errorRuntime 或宿主状态
ChatUIOptions静态 UI 配置layout、labels、bubble、sender业务初始化配置
Emits用户交互意图submit、switch-conversation、model-select用户操作
Slots局部结构扩展layout-header、layout-footer、request-error宿主页面
Input contract

受控与非受控输入

传入 inputValue 时由宿主控制，变更通过 update:inputValue 派发；没有传入时，ChatUI 使用内部草稿。组件生命周期内不切换两种模式。

'' 表示明确清空，undefined 不会作为输入值传递到底层 Sender。

Layout contract

布局由 Options 决定

Header、左 Aside、Main、Footer 和右 Aside 是稳定布局区域；桌面断点为 960px，移动端左栏强制使用 Drawer。

右 Aside 只有配置为对象时才创建；MCP 面板可以作为它的默认内容。

Slot 的价值：保留外层结构，替换局部内容

宿主可以替换 Header、Aside、Main、Footer 或错误展示，同时继续复用 ChatUI 的滚动、布局、响应式和输入状态管理。

自定义 Header 和输入区前置内容packages/chat-cases/src/cases/tiny-robot/TinyRobotAssistant.vue
<TrChat :runtime="runtime">
  <template #layout-header>
    <TinyRobotWindowHeader />
  </template>

  <template #composer-before="{ submit }">
    <TinyRobotComposerTools :submit="submit" />
  </template>
</TrChat>
08

Runtime 设计

Runtime 对上提供稳定协议，对下可以连接 Kit、Store 或自研数据层。

ChatRuntime 公开协议packages/chat/src/types/runtime.ts
interface ChatRuntime {
  conversations: ChatReadable<readonly ChatConversationInfo[]>
  activeConversation: ChatReadable<ChatConversation | null>
  composer: ChatComposerRuntime
  actions: ChatRuntimeActions
}
State surface
conversations会话摘要列表，供历史区展示。
activeConversation当前会话、消息、请求状态和错误。
composerdisabled、submitDisabled、模型和 MCP 状态。
actionssend、abort、会话 CRUD 等业务动作。
Integration paths
新项目useLocalChatRuntime 自动组装 Conversation、Provider 和 MCP。
已有 KituseKitChatRuntime 复用已有 Conversation。
自有数据层实现 ChatRuntime 协议，再交给 TrChat。
