界面与交互配置 ​

本文介绍如何通过 ui 配置和插槽调整 TrChat 的布局、输入区、消息展示及交互，以及如何单独使用界面组件 TrChatUI。首次接入见 快速上手。

界面配置与定制 ​

按照 快速上手 接入 TrChat 后，可以通过 ui 配置和插槽调整界面。需要直接提供显示数据并自行处理界面事件时，参考仅使用界面组件。

ui 是一个界面配置对象，用于设置布局、文案和各区域的显示方式；只需配置需要调整的部分，其余使用默认值。常用的字段如下，具体配置见后续示例：

ts
import type { ChatUIOptions } from '@opentiny/tiny-robot-chat'

const ui: ChatUIOptions = {
  layout: {}, // 页面布局、侧栏和浮动窗口
  labels: {}, // 按字段修改界面文案
  history: {}, // 历史会话列表
  welcome: {}, // 欢迎区内容
  prompts: {}, // 推荐问题
  sender: {}, // 输入区配置
  bubble: {}, // 消息展示配置
}

将配置好的 ui 传给 TrChat：

vue
<TrChat :runtime="runtime" :ui="ui" />

下面介绍常用配置和示例，完整字段见 界面配置。需要自定义界面内容时，见 插槽定制。

基础布局 ​

调整内容宽度、侧栏显示和空会话输入区的位置，适应不同页面布局。

loading

此演示使用 TrChatUI 展示布局效果，相同的 ui 配置也适用于 TrChat。

通过 ui.layout 设置布局，常用字段如下：

配置用途和可选值默认值
contentMaxWidth消息、欢迎区和输入区的最大内容宽度；支持数字或 CSS 长度，如 640、'80%'980，数字单位为 px
showScrollToBottom是否显示内置回到底部按钮；分享等场景可设为 falsetrue
leftAside左侧栏配置对象；设为 false 隐藏整个左侧栏显示侧栏，默认收起
leftAside.width左侧栏展开宽度，单位为 px300
leftAside.collapsedWidth左侧栏收起宽度，单位为 px56
leftAside.defaultOpen是否默认展开，之后可通过界面按钮切换false
composer.welcome空会话时的输入区位置：'footer' 位于页面底部；'center' 随内置欢迎区居中显示，需保留默认内容布局、欢迎区和输入区'footer'

例如，缩小内容宽度并默认展开左侧栏：

ts
const ui: ChatUIOptions = {
  layout: {
    contentMaxWidth: 640,
    leftAside: { width: 240, collapsedWidth: 48, defaultOpen: true },
    composer: { welcome: 'center' },
  },
}

已有消息或隐藏欢迎区时，输入区仍位于底部。通过插槽自定义主区或空会话内容时，输入区的居中位置需自行设置，详见插槽说明。

完整字段和默认值见 布局配置。

聊天界面默认使用浏览器视口高度。嵌入已有页面时，可将 TrChat 放入高度明确的容器，并设置 --tr-layout-height: 100%，使界面填满该容器。例如，将高度设为 600px：

vue
<template>
  <main class="chat-page">
    <TrChat :runtime="runtime" />
  </main>
</template>

<style scoped>
.chat-page {
  --tr-layout-height: 100%;
  height: 600px;
}
</style>

调整宽度与间距 ​

消息列表与输入框默认对齐，回到底部按钮默认位于右侧。在组件或父容器上设置 CSS 变量，可以调整内容宽度、内边距和按钮位置：

css
.business-chat {
  --tr-chat-ui-content-max-width: 800px;
  --tr-chat-ui-content-padding-inline: 20px;
  --tr-chat-ui-header-padding: 16px 20px 8px;
  --tr-chat-ui-footer-padding: 8px 20px 16px;
  --tr-chat-scroll-button-align: center;
}

完整变量和默认值见 CSS 变量。

配置欢迎区和推荐问题 ​

设置欢迎内容和推荐问题，帮助用户开始对话。

loading

没有消息时，通过 ui.welcome 设置欢迎标题和描述，通过 ui.prompts 提供推荐问题，帮助用户开始对话。

配置用途默认值
welcome.title欢迎标题，类型为 string'TinyRobot AI 助手'
welcome.description欢迎描述，类型为 string'您好，我是TinyRobot，您专属的 AI 智能专家'
prompts.items推荐问题数组；每项的 label 为必填显示文字，description 为可选补充说明[]，不显示推荐问题
prompts.wrap是否允许推荐问题换行，类型为 booleanfalse

例如，设置项目助手的欢迎内容和两个推荐问题：

ts
const ui: ChatUIOptions = {
  welcome: {
    title: '项目助手',
    description: '选择一个问题开始，或输入自己的问题。',
  },
  prompts: {
    wrap: true,
    items: [
      { label: '解释代码', description: '请解释这段代码的作用，并给出使用建议。' },
      { label: '撰写周报', description: '请帮我整理本周工作，生成一份简洁的周报。' },
    ],
  },
}

点击推荐问题会触发 prompt-click，不会自动填入或发送。下面使用 Sender 的模板扩展将问题填入输入框，用户可编辑后发送：

ts
import { shallowRef } from 'vue'
import { TrSender, type TemplateItem } from '@opentiny/tiny-robot'
import type { ChatPromptClickPayload } from '@opentiny/tiny-robot-chat'

const inputTemplate = shallowRef<TemplateItem[]>([])
ui.sender = { extensions: [TrSender.template(inputTemplate)] }

function handlePromptClick({ item }: ChatPromptClickPayload) {
  inputTemplate.value = [{ type: 'text', content: item.description || item.label }]
}
vue
<TrChat :runtime="runtime" :ui="ui" @prompt-click="handlePromptClick" />

将 ui.welcome 或 ui.prompts 设为 false 可隐藏对应区域。发送首条消息后不再显示欢迎内容；返回新会话可重新查看。

更多展示配置见 Welcome 和 Prompts。

控制欢迎页显示 ​

默认在没有可见消息时显示欢迎页。应用也可以通过 is-empty 自行决定，例如仅在没有活动会话时显示：

vue
<TrChat :runtime="runtime" :is-empty="!activeConversation" />

activeConversation 为应用当前选中的会话。已有会话即使尚无消息，也会保持工作区布局。此设置同时影响页头插槽的状态和输入框位置，TrChatUI 同样适用。

配置输入区 ​

为输入框添加提及、可编辑模板和自定义按钮，满足不同输入需求。

loading

示例通过 ui.sender.toolbar 配置“写报告”和“常用问题”，分别填入可编辑模板和预设问题；通过 sender-footer-right 添加“使用说明”，配合 sender-header 展示操作提示。

点击“使用说明”显示或隐藏提示，再点击“写报告”或“常用问题”查看提示更新。输入框上方可按需显示标签或提示，隐藏后不保留空白：

vue
<template v-if="showHelp" #sender-header>
  <p>{{ helpText }}</p>
</template>

通过 ui.sender 调整输入框、配置提及和模板功能；通过 ui.sender.toolbar 或输入区插槽添加自定义按钮，无需重新实现消息发送和取消。

接收拖入和粘贴的文件 ​

TrChat 和 TrChatUI 会将 Sender 上的文件拖拽与粘贴事件交给宿主。宿主需在 sender-drag-over 中对原生 event 调用 preventDefault()，浏览器才会触发放置事件并交付文件。

loading
vue
<TrChatUI
  @sender-drag-over="({ event }) => event.preventDefault()"
  @sender-drop="({ event }) => handleFiles(event.dataTransfer?.files)"
  @sender-paste="(event) => handleFiles(event.clipboardData?.files)"
/>

拖拽事件参数包含原生 event 和 Sender 根节点 target。可在 sender-drag-enter 与 sender-drag-leave 控制拖拽提示层；粘贴事件收到 ClipboardEvent。上传校验、状态和请求由宿主负责。

回填、清空与聚焦 ​

可从外部填入提示词、清空文本或聚焦输入框。回填不会自动发送，清空文本不会移除附件或已选 Skill。

loading

TrChat 与 TrChatUI 均支持这些操作，完整说明见 TrChat 组件方法 和 TrChatUI 组件方法。

基础设置 ​

以下默认值为 Chat 的输入区配置，与单独使用 Sender 时不同：

配置用途和可选值默认值
placeholder输入框为空时的提示，类型为 string未发送时为 '请输入你的问题...'，发送中为 '思考中...'
mode'single' 单行、'multiple' 多行'multiple'
maxLength最大输入字数，类型为 number；超出后保留内容，但无法提交1000
showWordLimit是否显示字数统计，类型为 booleantrue
clearable有内容时是否显示清空按钮，类型为 booleantrue
defaultActions配置默认发送和清空按钮的提示等选项沿用内置按钮配置
extensions输入扩展数组，如提及、模板和联想[]

例如，限制为 300 字并修改按钮提示：

ts
const ui: ChatUIOptions = {
  sender: {
    placeholder: '请输入问题，最多 300 字...',
    maxLength: 300,
    showWordLimit: true,
    defaultActions: {
      submit: { tooltip: '发送给项目助手' },
      clear: { tooltip: '清空输入内容' },
    },
  },
}

输入值、发送中状态和禁用状态由 Chat 管理，不在 ui.sender 中设置。需要禁止输入或提交时，见 禁用输入与提交。

提及与模板 ​

TrSender.mention() 为输入框提供提及选择，默认输入 @ 触发；TrSender.template() 用于填入包含可编辑字段的模板。将它们放入 ui.sender.extensions 即可在 TrChat 中使用，默认不启用这些扩展。

ts
import { shallowRef } from 'vue'
import { TrSender, type MentionItem, type TemplateItem } from '@opentiny/tiny-robot'

const mentions: MentionItem[] = [
  { label: '产品组', value: 'product' },
  { label: '研发组', value: 'engineering' },
]
const currentTemplate = shallowRef<TemplateItem[]>([])

ui.sender = {
  ...ui.sender,
  extensions: [TrSender.mention(mentions), TrSender.template(currentTemplate)],
}

function fillReportTemplate() {
  currentTemplate.value = [
    { type: 'text', content: '请帮我写一份关于' },
    { type: 'block', content: '项目进展' },
    { type: 'text', content: '的报告。' },
  ]
}

提及项中的 label 是显示名称，value 是对应标识；模板中的 'text' 为普通文本，'block' 为可编辑字段。更新 currentTemplate 会替换输入框内容。

提及功能不会自动切换模型或助手。默认发送使用输入内容的纯文本；需要处理提及标识或模板字段时，见 结构化提交数据 和 发送前检查。

工具栏与自定义按钮 ​

ui.sender.toolbar 统一配置左侧高频操作按钮，支持数组或函数。TrChat 与 TrChatUI 使用相同配置。

loading
  • 追加按钮：使用 (defaults) => [...defaults, customItem] 保留内置按钮；自定义按钮配置 type: 'custom'、label、icon 和 onClick，通过 active 控制高亮。
  • 调整顺序：函数配置可基于 defaults 排序；数组配置完整替换按钮列表，未列出的按钮不显示。
  • 控制显隐：visible: false 隐藏按钮。
  • 控制禁用：disabled: true 禁止点击；设为 false 仍受模型能力和输入区禁用状态限制。
  • 适配窄屏：带图标的按钮在窄输入区自动隐藏文字、保留图标；label 仍用于无障碍名称和悬浮提示。

显隐和禁用不改变功能开关状态。清空、发送和停止按钮通过默认按钮配置管理。

需要自定义渲染时，使用 sender-footer 在左侧工具栏后追加内容，或使用 sender-footer-right 在右侧操作按钮前追加内容，详见插槽。

完整字段和规则见 Toolbar 配置。

配置消息展示 ​

通过 ui.bubble 调整消息展示：bubbleList 设置消息列表外观，bubbleProvider 设置内容渲染和错误提示，autoScroll 控制自动滚动（默认 true）；未配置时使用默认展示方式。

消息外观 ​

按消息角色设置头像、位置和气泡形状，区分用户消息与 AI 回答。

loading

演示中的自定义外观还将 AI 气泡背景设为透明；继续发送消息，新的消息会沿用当前配置。

通过 ui.bubble.bubbleList.roleConfigs 按消息角色设置外观。例如，分别配置用户消息（user）和 AI 回答（assistant）的头像、位置和气泡形状。

配置用途和可选值默认值
avatar自定义头像，例如通过 Vue 的 h() 创建的节点用户和 AI 分别使用内置头像
placement'start' 左侧、'end' 右侧user 为 'end'，assistant 为 'start'
shape'corner' 带角气泡、'rounded' 圆角气泡、'none' 不使用预设气泡形状'corner'

例如，给用户设置圆角气泡，给 AI 设置自定义头像：

ts
import { h } from 'vue'

const ui: ChatUIOptions = {
  bubble: {
    bubbleList: {
      roleConfigs: {
        user: { placement: 'end', avatar: h('span', '我'), shape: 'rounded' },
        assistant: { placement: 'start', avatar: h('span', 'AI'), shape: 'none' },
      },
    },
  },
}

更多配置见 头像和位置、气泡形状 和 BubbleList 属性。

需要自定义消息内容时，参考 Bubble 自定义渲染器。渲染器也可获取当前会话、消息状态和滚动容器，见自定义消息渲染上下文。

消息错误提示配置 ​

请求失败时，在对应的 AI 消息下显示错误提示，帮助用户了解失败原因。

loading

演示使用 useChatRuntime 展示默认错误提示，不包含自定义提示组件；默认提示不提供重试按钮。

通过 ui.bubble.bubbleProvider.errorRenderer 替换错误提示，传入 null 可关闭默认提示。CustomErrorRenderer 表示应用自行实现的错误展示组件。

ts
const customErrorUI: ChatUIOptions = {
  bubble: {
    bubbleProvider: { errorRenderer: CustomErrorRenderer },
  },
}

const disabledErrorUI: ChatUIOptions = {
  bubble: {
    bubbleProvider: { errorRenderer: null },
  },
}

errorRenderer 只控制提示的显示，不会改变请求的失败状态。

默认错误提示支持以下 CSS 变量：

  • --tr-bubble-error-color：文字颜色。
  • --tr-bubble-error-bg：背景颜色。
  • --tr-bubble-error-border-radius：圆角大小。

更多样式配置见 Bubble CSS 变量。

请求异常处理和操作失败通知见 请求失败时的提示。

用户消息目录 ​

开启 ui.anchor 后，可通过目录快速跳转到用户消息。定位后气泡短暂闪动，滚动时同步当前目录项；点击回到底部可返回最新内容。

loading
ts
const ui: ChatUIOptions = {
  anchor: {},
}

目录默认关闭，开启后在浏览器视口宽度小于 768px 时隐藏。应用也可以控制其显示，完整选项见 anchor 配置。

配置历史会话列表 ​

自定义历史会话的排序、筛选和分组，同时保留内置会话操作。

loading

浏览器宽度低于 960px 时，先通过界面按钮展开会话列表。

“置顶”和日期分组使用预设数据，不包含置顶操作或自动按日期归类。演示使用独立的本地存储保存示例会话，刷新后保留修改结果。

TrChat 默认使用 Runtime 的会话生成历史列表，支持切换、重命名和删除，无需额外传入 historyData。需要自定义排序、筛选或分组展示时，可通过 historyData 提供列表数据，继续使用内置列表和会话操作。

historyData 支持会话数组或 { group, items }[] 分组数组，列表按传入顺序展示；传入 [] 时显示空列表。group 是分组标题，items 是该组的会话数组，每项的 id 应对应 Runtime 中已有的会话。

下面以分组展示为例，按会话中的 metadata.group 展示“置顶”“昨天”“30天内”，未设置分组的会话放入“30天内”。metadata.group 是本例约定的字段，不是内置日期或置顶配置：

ts
import { computed } from 'vue'
import type { ChatHistoryData } from '@opentiny/tiny-robot-chat'

const groups = ['置顶', '昨天', '30天内']
const historyData = computed<ChatHistoryData>(() =>
  groups
    .map((group) => ({
      group,
      items: runtime.conversations.value.filter((item) => (item.metadata?.group ?? '30天内') === group),
    }))
    .filter(({ items }) => items.length > 0),
)
vue
<TrChat class="chat-history" :runtime="runtime" :ui="ui" :history-data="historyData" />

本例通过 computed 根据 Runtime 会话生成分组，列表会随会话新增、重命名或删除更新。

ui.history 用于配置菜单等展示选项，可不传，默认菜单包含重命名和删除；设为 false 可隐藏历史列表。例如，只保留重命名菜单：

ts
const ui: ChatUIOptions = {
  history: { menuItems: [{ id: 'rename', text: '重命名' }] },
}

左侧栏默认使用页面背景色，可通过 --tr-chat-ui-left-aside-bg 调整。选中颜色和圆角可通过 History 的 CSS 变量调整，在 TrChat、TrChatUI 或其父容器上设置即可：

css
.chat-history {
  --tr-history-item-selected-bg: #e4edfd;
  --tr-history-item-selected-color: #3964fe;
  --tr-history-item-border-radius: 8px;
}

完整展示配置见 History 属性 和 样式变量，程序调用见 会话管理。

插槽定制 ​

在页头、消息和输入区添加自定义内容。

loading

本示例使用以下插槽：

  • layout-header：自定义页头。
  • bubble-content-footer：添加消息反馈按钮。
  • composer-after：添加输入框下方的提示。

额度提醒等页头内容也可放在 layout-header 中，由应用控制显示和排版。

完整插槽列表及参数见 插槽。

右侧面板 ​

在聊天界面旁展示引用资料或结果预览。

loading

需要在会话旁展示引用资料、预览结果等内容时，通过 ui.layout.rightAside.panels 配置面板列表，再用 layout-right-aside-panel 插槽提供内容。

panels 是面板配置对象数组，默认为空数组 []，每项包含以下字段：

字段用途必填
id面板唯一标识，与 layout-right-aside-panel 插槽中的 panelId 对应。是
title面板标题，省略时显示 ui.labels.rightAsideTitle（默认 '详情'）。否

id 不能重复，也不能使用内置保留标识 mcp。右侧栏默认宽度为 320px，初始关闭；没有自定义面板或 MCP 数据时不会显示。

ts
const ui: ChatUIOptions = {
  layout: {
    rightAside: {
      panels: [{ id: 'preview', title: '结果预览' }],
    },
  },
}

浮动聊天窗口 ​

将聊天界面显示为可拖动、缩放的浮动窗口。

ui.layout.surface 用于配置聊天界面的显示方式，可在父容器中显示，也可作为浮动窗口显示。它包含以下两个属性：

  • mode：选择显示方式，默认 'normal'，显示在父容器中；设为 'floating' 时显示为浮动窗口。
  • floatingOptions：配置浮动窗口的拖动、缩放和尺寸限制，仅在 mode 为 'floating' 时生效。

floatingOptions 的常用字段如下：

字段用途默认值或行为
draggable是否允许拖动窗口true
resizable是否允许拖动边缘缩放窗口false

窗口默认支持拖动，下面开启缩放：

ts
const ui: ChatUIOptions = {

    surface: {
      mode: 'floating',
      floatingOptions: { resizable: true },
    },
  },
}

ts
import { shallowRef } from 'vue'

const floatingState = shallowRef<LayoutFloatingState>({
  placement: 'top-right',
  offsetX: 24,
  offsetY: 72,
  width: 520,
  height: 520,
})

<TrChat :runtime="runtime" :ui="ui" v-model:floating-state="floatingState" />

上例将窗口放在右上角，距右侧 24px、顶部 72px，宽高均为 520px。

未设置 floatingState 时，窗口默认居中，尺寸为 420px × 560px；实际尺寸不会超过浏览器可视区域。

响应式布局与侧栏缩放 ​

切换桌面和移动端布局，并在桌面布局下调整侧栏宽度。

loading

演示切换的是布局效果，不改变浏览器宽度；浏览器可视区域宽度低于 960px 时，即使选择桌面布局，也会自动使用抽屉。

侧栏支持两种布局，通过 ui.layout.leftAside.mode 或 ui.layout.rightAside.mode 设置，默认是 'dock'：

  • 桌面布局（'dock'）：侧栏与消息区并排显示。
  • 移动端布局（'drawer'）：侧栏以抽屉形式覆盖消息区。

浏览器可视区域宽度低于 960px 时，组件会自动使用抽屉布局。

仅缩小父容器不会触发自动切换；需要在较窄容器中使用抽屉时，将侧栏的 mode 设为 'drawer'。

桌面布局下，将侧栏配置中的 resizable 设为 true，可拖动边缘调整宽度，默认不启用。通过 minWidth、maxWidth 设置调整范围，单位为 px；抽屉布局不支持调整宽度。例如：

ts
const ui: ChatUIOptions = {
  layout: {
    leftAside: {
      defaultOpen: true,
      resizable: true,
      minWidth: 240,
      maxWidth: 420,
    },
  },
}

完整侧栏配置及默认值见 布局配置。

数据与事件处理 ​

通过 data 提供会话列表、消息和发送状态。用户发送消息、取消请求或切换会话时，在对应事件中执行项目的操作，并更新显示数据。

ts
import { computed, shallowRef } from 'vue'
import type { ChatMessageItem, ChatUIData } from '@opentiny/tiny-robot-chat'

const inputValue = shallowRef('')
const messages = shallowRef<ChatMessageItem[]>([])
const sending = shallowRef(false)

const data = computed<ChatUIData>(() => ({
  conversation: { title: '应用助手' },
  bubble: { messages: messages.value },
  sender: { loading: sending.value },
}))
字段用途默认值
conversation.title设置页头标题默认文案为“新对话”
bubble.messages提供消息列表[]
sender.loading显示发送中状态，并切换为取消操作false

常见操作通过以下事件通知项目处理：

用户操作事件项目需要处理
发送消息submit发起请求，更新消息和发送状态
取消发送cancel停止请求，恢复发送状态
新建会话create-conversation清空当前选择或创建会话，更新显示数据
切换会话switch-conversation更新选中会话、标题和消息
重命名会话rename-conversation保存新标题并更新列表
删除会话history-action判断 action.id === 'delete'，删除并更新数据

例如，监听 submit 和 cancel 处理发送与取消，通过 v-model:input-value 同步输入内容：

vue
<TrChatUI :data="data" v-model:input-value="inputValue" @submit="handleSubmit" @cancel="handleCancel" />

submit 和 cancel 只通知项目处理操作，不会自动请求或停止服务。发送后是否清空输入、何时追加回答，由对应的事件处理方法决定。

输入区的清空按钮会清空输入；使用 v-model 时，会同步更新绑定值。清空输入不会删除消息或取消请求。

完整数据字段见 ChatUIData，属性和事件见 TrChatUI API。

受控与非受控 ​

输入内容、侧栏开闭等界面状态支持两种管理方式：

  • 受控：由项目传入当前值并同步更新，适合填入预设问题、发送后清空输入或从外部打开侧栏。
  • 非受控：由组件维护状态，无需从外部同步更新，可按需设置初始值。

以输入内容为例，受控方式通过 v-model:input-value 绑定当前内容，inputValue 可初始化为 ''：

vue
<TrChatUI v-model:input-value="inputValue" @submit="handleSubmit" />

非受控方式不传入 inputValue，由组件维护输入。可通过 defaultInputValue 设置初始内容，默认 ''；后续修改该属性不会重置当前输入：

vue
<TrChatUI defaultInputValue="请介绍一下 TinyRobot" @submit="handleSubmit" />

两种方式都能通过 submit 获取文本，但不会自动发送请求或清空输入。

输入管理方式应在初始化时确定，不要在使用过程中切换。

右栏和浮动窗口也支持这两种方式：

状态受控方式非受控方式
右栏开闭v-model:right-aside-open使用 defaultRightAsideOpen 设置初始值，默认 false
当前右栏面板v-model:active-right-aside-panel-id使用 defaultActiveRightAsidePanelId；未指定有效面板时选择第一个可用面板
浮动窗口位置和尺寸v-model:floating-state不传入当前值，由组件维护内置窗口状态

左栏通过 ui.layout.leftAside.open 设置当前开闭状态，并在 left-aside-open-change 中更新；不设置当前值时，可通过 ui.layout.leftAside.defaultOpen 设置初始状态，默认 false。

完整属性和事件见 TrChatUI API，相关布局配置见 右侧面板 和 浮动聊天窗口。

ui.extensions ​

通过 ui.extensions.tabs 向内置扩展管理器注册 Skills 等应用能力。若同时提供 mcp，MCP 和应用页签会在同一面板中展示。原有 MCP 事件保持不变。mcp 是保留页签 ID，重复 ID 会被忽略。

import type { ChatUIOptions } from '@opentiny/tiny-robot-chat'

const ui: ChatUIOptions = {
  extensions: {
    defaultActiveTab: 'skills',
    tabs: [
      {
        id: 'skills',
        label: 'Skills',
        items: [
          {
            id: 'concise-answer',
            name: 'Concise Answer',

  },
}

扩展页签相关接口分为以下三类：

自定义消息渲染上下文 ​

自定义消息渲染器可通过 useChatRenderContext(props) 获取当前会话、消息状态和滚动容器。以下代码位于渲染器的 <script setup> 中：

ts
import type { BubbleContentRendererProps } from '@opentiny/tiny-robot'
import { useChatRenderContext } from '@opentiny/tiny-robot-chat'

const props = defineProps<BubbleContentRendererProps>()
const context = useChatRenderContext(props)

返回值为 ChatRenderContext | undefined，在 Chat 消息渲染区域之外调用时返回 undefined。字段均为响应式引用：

字段类型含义
scrollRootComputedRef<HTMLElement | null>消息滚动容器，挂载前为 null。
conversationIdComputedRef<string | null | undefined>当前会话标识。
messageKeyComputedRef<string>当前消息的稳定标识。
contentIndexComputedRef<number>当前内容索引。
streamStateComputedRef<'streaming' | 'finished' | 'unknown'>流式生成中、已结束或状态未知。

消息对象和服务端 ID 都可能变化时，请提供唯一且稳定的 renderKey。使用 messageKey 和 contentIndex 可区分渲染内容，无需解析 messageKey。

message.streamState 可显式指定流状态。未指定时根据当前请求的可追踪归属判断：历史消息默认按已结束处理；当前请求中的最新消息状态不足时为 unknown。loading 不决定流状态。

渲染器的定义与注册见 Bubble 自定义渲染器 和 Provider 配置。

常见问题 ​

页面没有高度或消息区不滚动 ​

聊天界面默认使用浏览器视口高度。嵌入已有页面时，检查父容器是否有明确高度，以及是否设置了 --tr-layout-height: 100%，见 基础布局。使用百分比高度时，祖先容器也需要有明确高度；使用 flex 布局时，检查消息区所在的子项是否允许收缩（如设置 min-height: 0）。
